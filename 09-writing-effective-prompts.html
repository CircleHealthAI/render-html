TL;DR. Write Review Assistant prompts like instructions for a careful auditor: structure around how your team already works, one concept per pass/fail question, name specific documents instead of using catch-alls, put scoping rules in the shared context, and test on charts where you already know the answer. The prompts get sharper with use — expect to revise after the first real run.

Start with the workflow

Structure your Review Assistants around how your team already audits charts. The core rule: same team plus same review timing can usually stay together. Different timing should usually be split.

For example, admission checks, weekly checks, and discharge checks should usually be separate assistants because they run at different points in the patient’s stay. This prevents early false failures (e.g. asking for a treatment plan one day after admission when it’s not due until day 7) and keeps each review focused on what should be complete at that moment.

Write specific pass/fail questions

Most Review Assistant questions should be pass/fail with a clear yes-or-no answer.

Good Avoid
Was the BPS completed? Is the BPS good?
Was the H&P signed by the physician? Are all admission documents complete, signed, and accurate?

Broad questions make the assistant decide too much on its own. Specific questions produce clearer results and are easier for your team to act on.

One concept per question

If completion, signature, timing, and content quality all matter, split them into separate questions. Instead of:

  • Was the H&P completed, signed, and filed within 24 hours?

Use:

  • Was the H&P completed?
  • Was the H&P signed by the physician?

When a chart fails, your team can see exactly what needs correction. Combined questions tell you something failed but not what.

Avoid catch-all questions

Questions like “Are all required admission forms completed?” force the assistant to first decide what counts as a required form, and different runs may interpret that differently. Instead, name the exact forms:

  • Was the Consent for Treatment completed?
  • Was the Financial Responsibility form completed?
  • Was the Release of Information completed?

The result is more consistent and the failure points are actionable.

Put scoping rules in the shared context

Each assistant has a shared context block that applies to every question. Use it to define:

  • Which document names or form names to look for.
  • Known alternate names for the same document.
  • What “complete” means.
  • Whether signatures are required.
  • When a missing document should fail.
  • When a question should be marked not applicable.
  • Whether the assistant should evaluate one document or all matching documents.

The questions stay clean and answerable. The context carries the extra instructions that help the assistant judge correctly.

Scope the assistant to the right document

If a question is about a specific form, the assistant should evaluate that form only — not borrow evidence from other documents. This matters most when multiple forms contain similar language (e.g. demographics appear on the face sheet, admission note, and intake form).

A helpful context line:

When a question names a specific document, evaluate only that document type. Do not use information from other forms to answer the question unless the question explicitly asks for cross-document consistency.

Be clear about not applicable

Some requirements only apply to certain patients. A pregnancy test may only apply to female clients. A psychotropic medication consent may only apply when the patient is prescribed psychotropic medication.

Put the condition in the question or the context:

If the patient is prescribed psychotropic medication, was the psychotropic medication consent completed?

Also be explicit about when a missing document should fail rather than be marked N/A:

If the required document is not found, mark the question FAIL. Do not mark it not applicable.

Do not repeat trigger timing in every question

If the assistant runs 72 hours after admission, every question does not need to say “within 72 hours of admission.” The trigger already controls when the assistant runs.

Use timing in the question only when the timing itself is what the assistant is judging, or when the assistant checks items with different due dates inside one run.

Pass/fail vs. summary

Question type When to use it
pass_fail Compliance judgments. The assistant should grade.
summary Extraction. The assistant should pull information from the chart and present it back without grading it. Useful for gathering session dates, treatment-plan details, or UR notes for the chart reviewer.

Medical necessity needs extra guardrails

For utilization review and medical necessity prompts, the assistant should not overstate severity when the chart evidence is vague. Strong medical-necessity context should tell the assistant to:

  • Rate conservatively.
  • Use direct chart evidence.
  • Require objective scores when relevant (COWS, CIWA, PHQ-9, GAD-7).
  • Pay attention to timelines, e.g. last use date vs. assessment date.
  • Treat boilerplate or copied-forward language carefully.
  • Use direct quotes for important findings.

Testing and refinement

After configuring a Review Assistant, run it on a few charts where your team already knows the expected answers. Then compare Circle’s results against the EMR.

If the assistant gets something wrong, the fix is usually one of:

  • Make the question more specific.
  • Add document-name variants.
  • Clarify what counts as complete.
  • Add a not-applicable rule.
  • Add a document-scoping rule.

Review Assistants improve fastest when the prompts are tested against real charts and refined based on specific misses — not based on hypothetical edge cases.
