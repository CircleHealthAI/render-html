Resync & Run

Both Run Review and Re-run Review become split buttons that mirror Start Session. The primary click runs on the data we already have (fast); the caret opens a menu where you can choose Resync & Run to pull the latest patient data from the EMR first. A stale-data warning nudges a resync when the chart looks out of date, and resync is locked for 5 minutes after the last sync.

State 1 · Fresh data default

Data synced recently. No warning. The menu shows both options, but there's no reason to resync, so it sits quietly as the secondary choice.

Patient data synced 12 min ago
Resync is slower. You may need to check back in a few minutes.

State 2 · Stale data warning

The chart looks out of date. A warning chip appears next to the button, and Resync & Run is promoted with a Recommended tag so people don't run a review on old data.

Patient data may be out of date. Resync before running

State 3 · Synced < 5 min ago cooldown

Resync is locked for 5 minutes after the last sync to avoid hammering the EMR. The option is grayed out and shows how long until it's available again. Hover it for the reason.

Patient data synced 2 min ago
Data was just synced. Resync unlocks 5 minutes after the last sync.

State 4 · Resync in progress slow path

After choosing Resync & Run, the button shows the long-running state and sets the expectation that they can leave and come back.

Pulling latest from the EMR. This can take a few minutes. You can leave this page; we'll keep going.
